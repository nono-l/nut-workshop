# ナット工房

人間と、あとから入った AI の両方が読める説明。

木工パズル。ネジを空き穴へ移し、板を落とす。

## このアプリがやること（だけ）

1. ネジをタップして持ち上げ、空いている穴をタップして置く。置いて初めて元の穴が空く
2. 板の**木**が乗っている穴には置けない。上の木に隠れたネジは外せない
3. ネジが 1 本だと、それを支点に板がぶら下がる
4. 板の穴がネジの軌道に乗ると吸い込む。木の胴体はネジに当たって止まる
5. 最後の1本を空き穴へ置けたら板は落ちる。持ち上げただけでは落ちない。全部落ちたらクリア
6. 制限時間とスター。全 20 面。ブースターは もどす / ネジ外し / 板はずし
7. 進行は端末の `localStorage`（キー `nut-workshop-save-v1`）。アカウントは持たない
8. 設定のデバッグをオンにすると穴番号とチートが出る。オフが本番。デフォルトはオフ

やらないこと: 物理ライブラリ、オンライン対戦、サーバー保存、元ネタの名前・キャラ・絵の複製。

## 遊び方

- ネジをタップ → 持ち上げる
- 光っている空き穴をタップ → 置く
- 木の下は置けない。先に上の板のネジをどかす
- 1 本残りの板は支点でぷらぷらする。穴がネジに重なると引っかかる
- **ネジ外し**だけ、空き穴なしでネジを壊せる
- **板はずし**は板を直接落とす
- 日英切替・きせかえ・にじいろ宝箱（今日 2 面クリア）

## ファイル分担

- `src/game/world.ts` … 盤・ネジ・板・覆い・振り子・衝突・入力。描画は持たない
- `src/game/render.ts` … canvas 2D。物理は持たない
- `src/game/levels.ts` … 20 面の穴と z。ロジックは持たない
- `src/game/store.ts` … zustand と localStorage。World は持たない
- `src/game/i18n.ts` … 日英。キーを増やすときは ja と en を同時に
- `src/game/audio.ts` … Web Audio の効果音。見た目は持たない
- `src/game/types.ts` … `LevelDef` / `SaveState` / 色
- `src/components/game/PlayScreen.tsx` … canvas の rAF と HUD。ここで `World` を new する
- `src/components/game/GameApp.tsx` … 画面切替だけ
- `src/components/game/HomeScreen.tsx` … ホーム
- `src/components/game/OtherScreens.tsx` … ショップ・きせかえ・ランキング・レベル選択
- `src/components/game/WoodUI.tsx` … 木目ボタンと設定
- `src/routes/index.tsx` … `GameApp` を載せるだけ
- `src/lib/auth/` … 足場。このゲームは使わない

## 不変条件（壊したらゲームが別物になる）

- ネジはタップだけでは消えない。空き穴に置いて初めて外れた判定
- ハンマー（ネジ外し）だけ、空き穴なしで破壊できる
- 木（穴ではない部分）が点を覆っていたら置けない・外せない。穴の開口だけ置ける
- 板の穴がネジに重なったら弾かず吸い込む。軌道に乗っていないネジは胴体で止める
- アンカー 1 本は支点の振り子。0 本は落下
- 持っている／飛ばしているネジに板はついていかない。残りのネジがあればそれでぶら下がる
- 最後の1本は空き穴へ置けて初めて外れる。持ち上げただけでは落ちない
- 上の板が覆っている下のネジには触れない
- 座標系は +Y 下向き。重力は下
- ネジを外す回転は反時計回り。締めるときは時計回り（canvas の正回転は時計回りなので角度は負）
- デバッグは設定トグル。オフでは盤に番号もチートも出さない

## コーディング方針（何も知らない AI 向け）

このリポジトリは、別セッションの AI が途中から読んでも迷わないことを優先する。
コードを読む相手は「昨日の会話を覚えていない AI」だと仮定する。

### コメントに書くこと

- **何をしているかより、なぜそうしているか** を書く。
- 関数・ファイルの先頭で、役割・やらないこと・前提・失敗して捨てた案を短く書く。
- 一見不思議な行には、制約か事故の理由を残す。
- 名前で分かる処理にはコメントを付けない。
- コメントは日本語。人間と AI の両方の第一言語を日本語に揃える。

### コメントに書かないこと

- コードを言い換えただけの説明
- 将来やるかもしれない機能の予告
- 捨てた案の長話。一行の理由で足りる

### 変更するとき

- 意図が変わったら、先にコメントを直してからコードを直す。
- コメントとコードが食い違っているなら、コメントが古い。コードに合わせてコメントを直す。
- 新しい制約を踏んだら、その場に一行で理由を残す。Issue やチャットにしか書かないと、次の AI は見えない。
- 上記の不変条件を破る変更は、README の不変条件も同時に直す。
